# educlopez/ui-craft — deep-read notes
- Verified: 473★, license MIT, last push 2026-11-20, branch main (source: GitHub API search 2026-11-24)
- What it is: A full "design engineering system" for AI coding agents: one core skill (ui-craft) + 25 slash-command lenses (craft, critique, audit, polish, animate, brief, tokens, remember, finalize, sddesign…), mirrored into 6 harness formats (.claude/.codex/.cursor/.gemini/.opencode/.agents), plus a Go installer CLI, an npm MCP gate server (ui-craft-mcp@0.9.1), a PostToolUse hook, and a deterministic 0-100 scorer. Positioned as "ship designer-grade UI by default".
- Scope: UI (both design-time guidance and verify-time gates; not prose)
- Key files read: README.md, VERSIONS.md, skills/ui-craft/SKILL.md (head), .agents/skills/critique/SKILL.md, .agents/skills/audit/SKILL.md, scripts/detect.mjs, hooks/hooks.json, evals/README.md, mcp/src/ layout, LICENSE
- Mechanics:
  - Core skill SKILL.md defines the "Ladder" (rung 0 ask → 1 direct commands → 2 persist brief/tokens/remember → 3 enforce MCP gates+CI) and four "knobs" (CRAFT_LEVEL default 7, MOTION_INTENSITY 5, VISUAL_DENSITY 5, DESIGN_VARIANCE per-surface) that gate which passes run (e.g. CRAFT_LEVEL 8+ runs the Polish Pass).
  - Surface "recipes" (recipe-dashboard/landing/auth.md) hold numeric limits (hero subtext ≤20 words, eyebrow budget, form column width) and a 10-item acceptance bar the agent must pass before reporting done.
  - Screenshot-first reviewing: critique/audit mandate visual capture at 3 viewports (1280/768/375) via Playwright MCP → Chrome MCP → agent-browser → ask user; code-only reviews must be labeled `[CODE-ONLY REVIEW]`.
  - Deterministic layer: scripts/detect.mjs (zero-dep Node scanner for AI-slop anti-patterns in CSS/JSX/TSX/Vue/Svelte, CLI+JSON+SARIF output, --fix mode, URL scanning via puppeteer/fetch); mcp/src/tools implements check_anti_slop, tokens_lint, acceptance_bar, score_ui, check_fold, route_task, ux_coverage — each with a .test.mjs.
  - Score = 100 − anti-slop critical×8/major×4/warn×1 − token findings×2 − a11y critical×8/major×4; ux_coverage deliberately returns markers (present/partial/missing/not-needed/unknown) instead of a number and never gates.
  - Go CLI (137 .go files) auto-detects harness (Claude Code/Cursor/Codex/Gemini/OpenCode), does idempotent config writes with backup + rollback on failure; platform-support table in README is honest about untested binaries (macOS Intel "never tested"; 5 shipped Windows bugs including a rollback bug that deleted files).
  - Cursor plugin wires a preToolUse hook running detect.mjs before every file write.
- 3 non-obvious ideas worth adopting:
  1. ux_coverage's refusal to score: markers instead of a number, because "a number converts `not-needed` into a failure" — coverage is reported next to quality, never merged into score_ui. Report-only tools that never gate.
  2. Put the protocol in the tool's response, not just reference docs: v1.0.19 found the fold protocol was invoked 4/7 times once it lived inside the MCP reply; v0.9.0 keeps markers + no-score rule in every lookup with a test asserting they stay there.
  3. Distribution-manifest discipline: pinned `ui-craft-mcp@0.9.1` everywhere (avoids implicit upgrade on first launch), GoReleaser SHA-256 + npm trusted publishing with provenance; plus a drift gate that checks the generated markdown fallback is byte-stable with the server data.
- Flaws / weaknesses:
  - Very large surface area (246 mirrored SKILL.md files, 95 more under cli/ assets) — maintenance-heavy mirrors; a comment in each mirror says "do not edit here", so generation is required but the generator is inside cli/.
  - `curl | bash` install is the recommended path (checksum verified, but still remote execution); `npx -y ui-craft-mcp@0.9.1` runs a bundled JS server on install.
  - Critique claims of "Nielsen × 6 design laws × 5 personas" live in prompt text; the deterministic scorer only covers anti-slop/tokens/a11y, so the headline "scoreable critique" is partly LLM self-assessment.
  - Same-author evals: VERSIONS.md admits "the same author wrote the items and ran the check" — discrimination shown, validity not.
  - README buries the impeccable inspiration; you must read VERSIONS.md to learn lineage.
