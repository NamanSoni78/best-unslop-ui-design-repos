# pbakaus/impeccable — deep-read notes
- Verified: 115,853★, license Apache-2.0, last push 2026-11-23, branch main (source: GitHub API search 2026-11-24)
- What it is: A "design vocabulary" system for coding agents: a 24-command skill (critique, polish, bolder, quieter, distill, ...), a 62-rule deterministic Rust slop/quality detector, a live in-browser variant iteration mode, and a design hook that scans every UI file the agent edits. Ships per-harness builds for ~20 agents (Claude Code, Cursor, Codex, Copilot, Devin, Grok, ...); the skill text drives a self-contained Rust engine binary (ENGINE_VERSION 0.1.27) downloaded once to `~/.impeccable/bin/`.
- Scope: both (UI design rules + copy tells like em-dash-overuse, marketing-buzzword, aphoristic-cadence, theater-slop-phrase) + tooling/aggregator across harnesses
- Key files read: README.md, .claude/skills/impeccable/SKILL.md, reference/craft-floor.md, crates/foundation/src/registry.rs (rule list), crates/detect/src/list_rules.rs, engines.rs (head), docs/ENGINE.md, docs/COMP-FIDELITY.md (head), crates/live/src/copy_edit_agent.rs (bypass flags), NOTICE.md, PRODUCT.md (head), crates/hook/src/ listing, .claude/skills/impeccable/reference/ listing (46 playbooks)
- Mechanics:
  - Commands: 24 verbs in 6 groups — steer (bolder, quieter, distill, colorize, typeset, layout, animate, delight, overdrive), review (critique = scored UX heuristic review; audit = a11y/perf/responsive P0-P3), finish (polish, harden, clarify, adapt, optimize, onboard), live (live, generate), plan/setup (shape, init, document, extract), plus deprecated `craft`. Each has its own playbook in reference/*.md (46 files).
  - Context files: `/impeccable init` writes PRODUCT.md (users, purpose, constraints) by reading the code and asking only what it can't infer; `document` captures the existing visual system into DESIGN.md; every command reads both. Four "modes" (Persuade/Operate/Read/Experience) scale ambition per surface.
  - Detector: `npx impeccable detect src/` — no LLM, no API key. 62 built-in rules in a Rust registry, 31 category "slop" + 31 "quality". Slop rules include overused-font (Inter/Roboto/Fraunces/Geist/Plus Jakarta Sans/Space Grotesk), ai-color-palette, cream-palette, gradient-text, nested-cards, icon-tile-stack, hero-eyebrow-chip, kicker-above-heading, numbered-section-labels, italic-serif-display, side-tab, border-accent-on-rounded, gpt-thin-border-wide-shadow, repeating-stripes-gradient, codex-grid-background, em-dash-overuse, marketing-buzzword, aphoristic-cadence, theater-slop-phrase; quality rules include low-contrast, gray-on-color, cramped-padding, tiny-text, skipped-heading, tight-leading, line-length, text-occlusion, first-viewport-column-overflow. Rules carry skill_section/skill_guideline so findings point back into the playbook.
  - Two engines: static HTML/JSX/TSX engine (parser, cascade, static DOM) for pattern rules on source; browser engine (Chrome/CDP discovery, screenshot) for rendered rules (contrast, tiny text). Rule packs can extend the registry (testpack IDs visible). Output: human, --json, --github Actions annotations, --sarif 2.1.0; exit 2 = findings, 1 = scan failure. Inline ignores `<!-- impeccable-disable rule: reason -->` plus `--report-unused-ignores` so stale waivers fail CI; `ignores add-value overused-font Inter --reason "Brand font"`.
  - Hook: installer offers a design hook (crates/hook: before_edit, build_completion, stop_baseline) that scans each UI file the agent edits and feeds findings back — README's claim: "This is where most slop gets caught." Hook budget ~50 ms/edit (image samples CacheOnly). README warns hooks run outside model approval in Claude Code even when you deny the model's commands; `--settings '{"disableAllHooks": true}'` disables.
  - Live mode: `/impeccable live` opens the dev server with an overlay; pick an element, cycle hot-swapped variants, accept writes back to source (Vite/Next/SvelteKit/Astro/Nuxt/plain HTML). Apply sends staged copy edits to a polling chat agent; if none polled in the last minute it runs `codex exec --dangerously-bypass-approvals-and-sandbox` (or `claude --print --permission-mode bypassPermissions`) from PATH with environment inherited — controllable via IMPECCABLE_LIVE_COPY_AGENT=chat|off (crates/live/src/copy_edit_agent.rs:1524,1552).
  - Comp-fidelity path: for new landing pages it can generate an image comp first, then `comp-diff.mjs` mechanically scores the build against the comp (SSIM structure, color histograms, high-frequency detail per region, band alignment) and writes side-by-side/heatmap/region crops with verdicts match/drift/missing/contradicted — explicitly replacing "the model judging its own reproduction from memory" (docs/COMP-FIDELITY.md).
  - craft-floor.md: the 44-line quality floor loaded "immediately before any UI edit" — bans: kicker/eyebrow above a heading (hard ban), nested cards, gradient text, side-tab accent bars, hard offset shadows, monospace-as-costume, emoji-as-icons, geometric masks for organic contours; verify list includes theming browser surfaces (selection color, caret, scrollbars, focus rings) as "the cheapest signal a page was built rather than assembled."
- 3 non-obvious ideas worth adopting:
  1. Rule registry entries carry `skill_section`/`skill_guideline` pointers back into the playbook, so a deterministic finding lands with the design rationale attached — detector and prose stay in sync instead of drifting.
  2. Comp-fidelity: replacing the model's self-assessment of "does the build match the design" with a mechanical SSIM/color/detail/band scorer that emits per-region verdicts and calibrated thresholds (sibling comps of the same world score 55-59% vs 100% self-match).
  3. The `--report-unused-ignores` CI pattern: inline waivers that no longer match a finding fail the build, so suppressions can't silently outlive their reason — directly transferable to any linter-based slop gate.
- Flaws / weaknesses:
  - The live-mode Apply fallback spawning a CLI agent with all approvals, permission checks, and sandboxing off (`--dangerously-bypass-approvals-and-sandbox` / `bypassPermissions`) is a genuine security footgun, honestly documented but on by default when no chat session is polling.
  - Closed-loop commercial ecosystem: skill fetches visual directions from the impeccable.style catalog on every new design, and telemetry (opt-out via DO_NOT_TRACK/`telemetry off`) records which directions were picked; the docs site holds most command documentation, so the repo is not fully self-contained.
  - Engine is a downloaded prebuilt binary (first run downloads into `~/.impeccable/bin/`) — source is in-repo but users typically run opaque binaries; checksums file exists (engine-checksums.txt) which mitigates.
  - 62 rules and 24 commands are opinionated and model-generation-specific (rules literally named gpt-thin-border-wide-shadow, codex-grid-background — they will age); detector on source files (JSX/TSX) gets pattern rules only, so rendered-page rules need a URL scan.
  - Distribution complexity is huge (per-harness folders, plugin marketplaces, VS Code extension, Chrome extension) — a lot of surface to keep consistent; skill version 4.10.0 vs engine 0.1.27 double versioning.
