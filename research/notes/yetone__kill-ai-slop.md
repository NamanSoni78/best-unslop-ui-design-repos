# yetone/kill-ai-slop — deep-read notes
- Verified: 1,474★, license Apache-2.0, last push 2026-09-15, branch main (source: GitHub API search 2026-11-24)
- What it is: Two artifacts by yetone (Anthony Fu): a multilingual (EN/ZH/JA/KO) "field guide" website cataloguing 33-35 AI-slop tells with interactive before→after demos (built as a rebuttal of its own catalogue), and an agent skill that turns the catalogue into a workflow: a dependency-free static scanner (`scan.mjs`) finds code-level signals, the model triages slop-vs-intentional, reports, and only then fixes.
- Scope: both (visual tells + copy tells like 14 "AI copywriting voice"), detection/cleanup focus rather than design generation
- Key files read: README.md, skill/SKILL.md (full), skill/references/taxonomy.md (Color section + Evolved slop section), skill/references/detection.md (head), skill/scripts/scan.mjs (head + rule list), skill/scripts/scan.test.mjs (head), .github/workflows/test.yml (head), website/src/data/catalogue.ts (structure grep)
- Mechanics:
  - Taxonomy: 35 tells in 7 groups (color/type/copy/component/motion/layout/evolved), two tiers — Classic (indigo→violet gradient, gradient-clip headlines, warm "cozy" palette, default semantic palette, one-hue status boxes, gradients-as-atmosphere, serif-italic emphasis, kickers, flat hierarchy, glowing status dots, pastel icon tiles, glassmorphism, badge spam, AI-drawn SVG icons, invented stat rows, 01/02/03 markers, cards-in-cards) and Evolved slop (33 Inter everywhere, 34 "tasteful terminal", 35 "editorial dashboard" — second-wave uniform: "scolded out of indigo gradients, the model's new shorthand for 'taste' is cream + display serif + one deep accent").
  - Core doctrine: "slop is the *absence of a decision*. A tell is only slop when it's a default nobody chose. The same element, chosen and defended, is fine." Detection patterns document false positives per tell ("a brand that genuinely is purple; slop is the *combination*").
  - Scanner: `node skill/scripts/scan.mjs <root>` — pure Node, no deps, "NEVER edits files", skips build dirs/lockfiles/minified, realpath-based self-exclusion, escapes terminal control chars; outputs grouped file:line hits or --json. `--only/--skip` by tell id, `--exclude` paths, `--rules=extra.mjs` custom tells (shipped rules.ru.mjs example for Russian copy, noting JS `\b` is ASCII-only so non-Latin patterns need plain substrings). In-source suppression via `deslop-ignore` / `deslop-ignore-next-line <id>` / `deslop-ignore-file` comment directives, id-scoped so new tells still surface.
  - Workflow in SKILL.md: Scope → Scan → Triage ("This is the step that separates this skill from a lint rule" — confirm each hit by reading code, keep defended choices) → Report in a fixed grouped format with proposed fixes, then ask which groups to apply → Fix (minimal diffs, prefer token/component-level edits, never invent brand colors, re-run scanner to confirm count dropped).
  - Guardrails section: respect authorship ("When unsure whether something is slop, ask — don't strip it"), small reviewable diffs, never `git add -A`, no new dependencies, "a passing scan is not the same as a better page".
  - Website: Astro static, zero-JS-by-default, "paper + ink, one editorial red used like a proofreader's pen"; catalogue.ts (800+ lines) is the single source of truth shared with the skill.
  - Tests: scan.test.mjs (202 lines, node:test) builds temp projects and asserts scanner behavior; CI workflow runs scanner tests on pushes touching skill/.
- 3 non-obvious ideas worth adopting:
  1. The "Evolved slop" tier — cataloguing the second-wave defaults (tasteful terminal, editorial dashboard, cream+serif) that arise precisely from anti-slop pressure — an explicit acknowledgment that the tells drift as models learn to avoid round one.
  2. Triage-as-separate-step with "every match is a lead, not a verdict" + id-scoped in-source suppression directives — the lint/`eslint-disable` pattern applied to slop detection, so suppression is per-tell and re-scans stay useful.
  3. The field-guide website as the taxonomy's source of truth (catalogue.ts shared with the skill) with each tell rebuilt in plain HTML as an interactive before/after — teaching material and detector kept in one data file.
- Flaws / weaknesses:
  - Small project: 1,474★, last push 2026-09-15 (two months stale), single author; no evals, no browser rendering — the scanner is regex-only (its own detection.md admits rendered outcomes like contrast can't be grepped).
  - Only 35 tells vs impeccable's 62 rules with rendered-page engine; no CI integration story beyond manual runs (no SARIF/GitHub annotations).
  - Fix phase depends on model adherence to fixes.md prose; no verification loop other than "re-run the scanner" (which the skill itself notes isn't proof of a better page).
  - Website and skill duplicate taxonomy knowledge (catalogue.ts vs scan.mjs rules vs taxonomy.md — three places to update).
- Safety & license: Apache-2.0. Scanner is dependency-free, read-only, never edits files; no hooks, no telemetry, no MCP servers. Website demos are original rebuilds "for commentary, criticism, and education" (not screenshots of real products). Nothing executed by me.
- Lineage: original taxonomy by yetone; installs through the vercel-labs `npx skills` universal installer; no vendored third-party content found; rule extension format documented for community tells.
- Install (from README): `npx skills add yetone/kill-ai-slop` (scanner directly: `node skill/scripts/scan.mjs path/to/project`)
- Tier suggestion: B — the cleanest conceptual articulation of the problem ("slop is the absence of a decision") plus a genuinely safe, tested, zero-dep scanner with per-tell suppression, but small scope, regex-only detection, and stale push keep it below the heavyweights.
