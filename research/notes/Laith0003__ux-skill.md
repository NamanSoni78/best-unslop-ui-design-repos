# Laith0003/ux-skill — deep-read notes
- Verified: 112★, license MIT, last push 2026-11-12, branch main (source: GitHub API search 2026-11-24)
- What it is: A large local "design intelligence engine" distributed as a Python package (pip `uxskill` / `npx uxskill@latest`): a deterministic 7-axis synthesizer that compiles briefs into complete WCAG-gated design systems (DTCG token format), 12 queryable JSON data manifests (84 styles, 176 palettes, 148 components, 171 anti-pattern rules, 160 brand specs…), a 171-rule anti-slop linter with optional headless-Chromium render probes, 18 slash commands, 25 MCP tools, and 17-IDE installers. Plus a Figma companion skill.
- Scope: both (UI engine + UX copy commands like ux-copy.md; primarily UI)
- Key files read: README.md (head ~120), NOTICE, PRIVACY.md (grep), bin/ux-lint.py, engine/ layout, engine/linter/ (listing + sizes), data/anti-patterns.json (sampled 2 of 171 rules), figma-skill/ux-skill-foundations/SKILL.md, commands/ listing, tests/ listing
- Mechanics:
  - What the 580 md files are: 276 in references/ (craft guidance, surface playbooks), 210 in engine/ (rulepack guidance per axis: border/type/layout/content/imagery), 25 docs, 25 command definitions (ux-a11y, ux-audit, ux-design, ux-discover, ux-lint, ux-polish…), plus 17 translated READMEs — content, not filler mirrors.
  - 349 scripts = the Python engine itself (116 engine/*.py files: foundations, generator, evaluator, contracts, discovery, brand, image_extract, installer…) + bin shims + tests; it is a real offline codebase, "No LLM ever called" in the v4 build path.
  - Linter: engine.lint reads 171 rules from data/anti-patterns.json, each with regex detection + severity + category + scope (e.g. "Inter as display font", "Unsplash photo with no alt"); --threshold sets exit-code severity; --json CI mode; `--render` opens pages in headless Chromium at desktop+phone widths and probes focus rings, hover/press latency, Escape focus loss, press-motion under reduced-motion.
  - System build: `uxskill system build --brand '#3366FF' --brief … --out design-system` → tokens.css, fonts.css with metric-matched fallbacks, art/, system-report.md; WCAG gate measures every text/control/focus pairing in light+dark at standard and high contrast — "a system that fails is not written".
  - `/ux-polish` loops lint→fix→re-lint until score ≥90 or three rounds; `/ux-design` loads exactly one surface playbook so dashboard builds never read hero rules.
  - Figma skill: exports tokens as Figma variables with modes (light/dark, standard/high-contrast, comfortable/compact, LTR/RTL, full/reduced motion), component contracts bind every property to a role variable, round-trip import gives same names/values.
- 3 non-obvious ideas worth adopting:
  1. Data-driven linting: all 171 rules live in a JSON manifest (id/name/severity/regex/scope) separate from the engine — rules are data anyone can audit or extend without touching code.
  2. "A system that fails is not written": the WCAG gate runs inside the generator (refuse-to-write on any failing pairing, in both contrast modes) rather than as a post-hoc audit.
  3. Contract round-trips between code and design tools: the same token set exports to Figma variables/modes and imports back from a Figma variables export — one system held by both, with "what Figma cannot hold" listed in export notes.
- Flaws / weaknesses:
  - README is an exhausting marketing wall (badge stack, "strongest UX plugin", comparison pages, Discord, PyPI/npm/github links); claims like "13101 passing tests" and "17 IDEs" are hard to verify from the tarball (94 test files exist; IDE installers present).
  - Vast scope invites brittleness: 12 manifests + 5 sub-agents + 25 MCP tools + 18 commands from one author; quality across all surfaces is unverifiable without running it.
  - Regex detections in JSON rules share the usual false-positive limits (e.g. the Inter-display regex is heuristic on font-size thresholds).
  - The `--render` probes need headless Chromium (Playwright-class dependency) — the heaviest runtime requirement in this batch; pip/npm dual distribution multiplies install paths.
  - Despite "distinctive not generic" positioning, a deterministic synthesizer also risks its own convergence signature — the repo doesn't discuss second-order drift the way auteur does.
