# bitjaru/styleseed — deep-read notes
- Verified: 1045★, license MIT, last push 2026-11-23, branch main (source: GitHub API search 2026-11-24)
- What it is: A design-system-preservation toolkit for AI agents: one registered `styleseed` skill routing to 22 internal workflows (ss-build, ss-audit, ss-score, ss-verify, ss-tokens, ss-reference, ss-studio…), an engine of compiled rules (74 craft rules, 8 output grammars, 9 brand recipes, OKLCH palette generator), a deterministic code checker, and rendered-pixel verification. Sells "keep YOUR design decisions across screens/sessions" rather than a universal taste.
- Scope: both (UI + microcopy workflow ss-copy) — primarily UI; aggregator-style product with own engine
- Key files read: README.md, skills/styleseed/SKILL.md, workflows/ss-score/WORKFLOW.md, workflows/ss-update/references/update-preflight.md, engine/ARCHITECTURE.md, docs/DESIGN-JUDGMENT-EVALUATION.md, scripts/ listing, engine/.claude/skills/styleseed check
- Mechanics:
  - `.styleseed/STYLESEED.md` "lock" records project choices (skin, key color, font, radius, motion); every session re-reads it so decisions survive sessions.
  - ss-resolve compiles a per-task "effective rules" bundle (`.styleseed/effective-rules.md` or registry artifacts with per-artifact bundles + manifests with source hashes) instead of loading the 220KB handbook.
  - Deterministic checker `styleseed-check.mjs scan` with stable detector IDs: SS001 hardcoded colors, SS002 arbitrary pixel values, SS003 transition-all, SS004 motion without reduced-motion, SS005 focus suppression (blocking), SS006 unlabeled icon controls (blocking); SARIF + JSON output, `--gate` exit 3 on blocking findings; evidence gate (`evidence-gate.mjs attach`) with typed report paths and hashes; functional outcomes are separate from the 0-100 score and "cannot be offset by appearance points".
  - Quality gate loop: build → code score → pixel verify (screenshot spacing checks) → temporal gate (recorded frames/interrupts) → human acceptance; scores below 80 tell the agent to revise before presenting.
  - What the 293 scripts are: repo build/release/verification tooling — build-plugin-packages, build-evidence-pack, build-fault-pairs, s1-drift-metric, calibrate-render-faults, consensus-study, many Playwright browser tests (test-*-browser.mjs), fixtures — plus per-workflow scripts shipped with the skill (palette generator, screen compare, structure observation, studio-run). They are the repo's own CI/test/release machinery, not something installed agents run blindly; the installed skill runs styleseed-check.mjs, check-update.mjs, evidence-gate.mjs and workflow scripts.
  - engine/ is the source of truth: rules catalog (engine/rules/catalog.json), token layers, presets, and a `.claude/skills/styleseed` mirror (byte-identical to skills/styleseed/SKILL.md per diff) used for the marketplace/plugin packaging path.
  - BENCH-V1: a historical 120-rendered-cell benchmark (claimed +5.3 for gate vs raw rules; Codex +1.6, Claude −3.7 with raw rules) — raw evidence hosted on styleseed-demo.vercel.app, not fully in-repo; DESIGN-JUDGMENT-EVALUATION.md is an honest draft protocol ("no expert review or model comparison performed") with a 4-arm A/B/C/D design.
- 3 non-obvious ideas worth adopting:
  1. Honest negative-result benchmarking in the README headline: "raw rules alone were inconsistent (Codex +1.6, Claude Code −3.7), which is why StyleSeed ships a render→score→revise loop — not a prompt dump." Publishing the failure mode of your own naive approach.
  2. Registry-first artifact boundary with source-hash manifests and "never fall back to the global legacy bundle" — per-artifact rule bundles whose integrity (hashes, containment, coverage) is revalidated before scanning, making evidence tamper-evident.
  3. Three-gate separation (code / pixel / temporal) plus the explicit rule that functional completion is a separate axis "cannot be offset by appearance points" — anti-gaming by construction.
- Flaws / weaknesses:
  - Enormous surface (22 workflows, 74 rules, 8 grammars, 9 recipes, 7 skins, 119 repo scripts, huge docs tree) — steep cognitive load; the README itself is a marketing wall with many badges and upsell links to styleseed-demo.vercel.app.
  - Update preflight phones home (fetches https://styleseed-demo.vercel.app/version.json and GitHub releases) on first workflow per session; offline result is treated as "unknown", nudging constant updates — network dependency inside a local skill.
  - BENCH-V1 raw cells are on the demo site, not the repo (only references + an immutable-history rule found); the +5.3 claim can't be fully audited from the tarball.
  - Marketing copy says things like "a markdown file alone cannot block delivery" while the score gate is still LLM-mediated except for the 6 deterministic detectors.
  - One-author project with very ambitious claims ("Support experts, not replace them") — DESIGN-JUDGMENT-EVALUATION.md admits the expert-review protocol is still DRAFT/unrun.
