# vercel-labs/skills — deep-read notes
- Verified: TBD (metadata pending). Branch `main` (tarball path). MIT, "Copyright (c) 2026 Vercel, Inc." (LICENSE); ThirdPartyNoticeText.txt present. This is the npm package `skills` ("The CLI for the open agent skills ecosystem") and the skills.sh directory's companion repo. Node 22.20+.
- What it is: The `npx skills` package-manager CLI for agent skills: find/add/update/remove across 80+ agents (Claude Code, Codex, Cursor, OpenCode, ...), plus one shipped skill — `find-skills` — that teaches any agent to search and recommend skills. It is the dominant distribution rail that every other repo in this batch installs through. As a competitor to a planned "find-best-skills" skill, its quality bar and blind spots matter most.
- Scope: registry (CLI + directory + discovery skill).
- Key files read: README.md (150 lines, full); skills/find-skills/SKILL.md (141 lines, full); docs/creating-skills.md (discovery + registry sections); docs/troubleshooting.md (telemetry grep); src/find.ts (search mechanics grep); src/telemetry.ts (grep); package.json.
- Mechanics:
  - CLI: `npx skills find [query] [--owner]`, `add <owner/repo[@skill]>`, `use` (prompt without installing), `list/check/update/remove/init`, experimental `sync`/`install` with skills-lock.json. Content-hash lockfile (v2) with a precisely specified deterministic SHA-256 recipe (path+NUL+length+NUL+content, CRLF→LF, byte-sorted; test vectors printed in README.md:98-104); Git sources pin exact commits so restores are reproducible; `--frozen-lockfile` supported.
  - Search (src/find.ts): hits `https://skills.sh/api/search?q=...`; because "The search API requires every query term to match", the CLI auto-retries multi-term queries with each term dropped and merges exact/partial results; interactive fzf-style TUI, min 2 chars, debounced.
  - Registry model: skills.sh is the index; any public GitHub repo is discoverable — the CLI walks standard skill container dirs (skills/, skills/.curated/, .claude/skills/, plus a long tail of agent-specific dirs, documented in creating-skills.md "Skill Discovery") up to 3 levels deep, honoring .claude-plugin/marketplace.json manifests and opt-in `skills.sh.json` paths fields; frontmatter `metadata.internal: true` hides a skill from discovery (INSTALL_INTERNAL_SKILLS=1 to see it). No application, no review queue visible in this repo: publication is automatic opt-in by repo layout. Curation is effectively the leaderboard (skills.sh ranks by total installs) plus whatever skills.sh staff do server-side (not found in repo).
  - find-skills skill (the competitor to our planned find-best-skills), exact procedure: (1) understand domain/task; (2) "Check the Leaderboard First" — skills.sh ranked by total installs, with hardcoded examples "vercel-labs/agent-skills — React, Next.js, web design (100K+ installs each)" and "anthropics/skills — Frontend design, document processing (100K+ installs)" (find-skills/SKILL.md:48-49); (3) run `npx skills find [query]`; (4) "Verify Quality Before Recommending" — the entire quality bar: install count ("Prefer skills with 1K+ installs. Be cautious with anything under 100", SKILL.md:69), source reputation (official sources "vercel-labs, anthropics, microsoft" more trustworthy, SKILL.md:70), GitHub stars (<100 stars = skepticism, SKILL.md:71); (5) present name/description, install count, install command, skills.sh link; (6) offer to install with `-g -y`; fallback when nothing found: help directly or suggest `npx skills init`.
  - Telemetry: anonymous install events; repo+skill identifiers sent only for GitHub-confirmed-public repos; `DISABLE_TELEMETRY=1` / `DO_NOT_TRACK=1` disables telemetry and security-audit requests (troubleshooting.md:40, README.md:138-139). Telemetry never blocks install (src/telemetry.ts).
- 3 non-obvious ideas worth adopting:
  1. The lockfile content-hash recipe with published test vectors — makes "which exact skill files are installed" independently verifiable by third-party tools; pin-to-commit restore is the right reproducibility model for skills.
  2. Auto-retry query relaxation (drop each term in turn when the API ANDs terms) — small, practical search UX fix.
  3. `metadata.internal` + INSTALL_INTERNAL_SKILLS env gate — a clean way to ship private/WIP skills inside a public repo without polluting discovery.
- Flaws / weaknesses:
  - The find-skills quality bar is popularity + brand, full stop: no reading of the SKILL.md content, no license check, no maintenance check, no anti-slop or correctness vetting. A 5K-install skill that is 4,000 lines of padding outranks a 300-install excellent one.
  - Self-serving defaults: the skill's own Step 2 hardcodes vercel-labs/agent-skills as the top example, and Step 4's trusted-source list starts with vercel-labs — the registry operator biasing its recommendation skill toward itself and anthropics/microsoft; ComposioHQ/awesome-claude-skills is cited as a "popular source" (SKILL.md:123), a marketing list.
  - What it misses for OUR purposes: no category/quality taxonomy (no way to say "design taste" vs "design slop"), no eval signal, no lineage/vendoring awareness (a skill that vendors another is opaque to it), no license surfacing at recommend time, and leaderboard-by-installs structurally favors early big publishers.
  - English keyword search only as far as visible; `-y` global install default in the skill's Step 6 teaches agents to install third-party prompt-injection vectors into the user's global config without review.
- Safety & license: MIT. Installs execute nothing at install time (skills are files), but the CLI is the vector by which arbitrary third-party SKILL.md instructions enter agent context; the security posture is telemetry-side (security-audit requests on public repos) rather than content review. Telemetry is on by default (documented, opt-out). No hooks.
- Lineage: registry hub — nearly every repo in this batch installs through it (anthropics, emilkowalski, molveau, pstack, theclaymethod READMEs all show `npx skills add ...`). molveau's usage-numbers section reads install counts from skills.sh. find-skills' own recommendations hardcode anthropics/skills and vercel-labs/agent-skills. It does not vendor other repos; agent-skills (vercel-labs) is a separate repo.
- Install (from README): `npx skills add vercel-labs/agent-skills` (example usage; the CLI itself is `npx skills ...` with no install).
- Tier suggestion: B (registry category) — the ecosystem's standard rail with excellent install mechanics (lockfile, commit pinning), but its discovery/recommendation layer is popularity- and brand-driven with self-preferential defaults; a curated, content-aware finder (ours) has clear headroom over find-skills.
