# agiwhitelist/auteur — deep-read notes
- Verified: 936★, license MIT, last push 2026-08-06, branch main (source: GitHub API search 2026-11-24)
- What it is: A single 153-line SKILL.md "direct a website like a film" skill with 11 reference files, 6 templates, and 8 zero-dependency Node scripts (2,621 lines total). Art direction is committed in writing (commit-sheet) before code, assets are generated/sourced locally, and every ship is gated by an executable anti-slop linter (slopscan), a Playwright screenshot/motion QA loop, and a cross-route drift scanner.
- Scope: UI (build/direct/system registers; copy-tell bans touch prose only as UI text)
- Key files read: README.md, SKILL.md, scripts/slopscan.mjs (L1-280), scripts/motionqa.mjs (head), reference/ listing, templates/COMMIT-SHEET.md path, DESIGN.md, package.json, LICENSE
- Mechanics:
  - Three registers: build (conventional site), direct (cinematic scroll-directed), system (multi-screen product with a component contract and no-peak rule); routing table incl. edit/recon/audit; explicitly hands off foreign-UI polishing to /impeccable.
  - Commit-sheet gate: 7 fields must be filled with non-defaults BEFORE code — peak (the one wow moment), color (OKLCH + lightness as a NUMBER so it's checkable later), type (contrast-axis pairing + "why not Inter"), grid break, motion budget (≤3 scroll families), reflex check (first-order AND second-order category reflex + chosen deviation), house-tells broken (≥2 named self-tells with replacements).
  - slopscan.mjs: read-only zero-dep linter, regex tokenization over CSS blocks in css/scss/html/jsx/tsx/vue/svelte/astro/js; rules like AI_GRADIENT (≥2 stops in hue 250-290), GRADIENT_TEXT, TRANSITION_ALL, RAW_SCROLL_LISTENER, FONT_DEFAULT_SLOP (Inter/Space Grotesk first), GLASS_CARD (warn), CARD_CLONE_GRID (identical border-radius|padding|shadow triple), EYEBROW_EVERYWHERE, CREAM_DEFAULT (OKLCH lightness/chroma/hue window), em-dash copy, autoplay sound, video-no-poster, WebGL-without-reduced-motion, pointer-without-rAF; `/* auteur-allow: RULE_ID -- reason */` suppression requires a ≥10-char real reason.
  - motionqa.mjs: Playwright at 1440×900 DPR 2 with CPU throttle 4×, asserts min-FPS 50 and max long-task 50ms; comments insist headed runs (headless = software swiftshader floor), production build (dev server ≈ 2× frame cost), and that fullscreen shader passes are priced per pixel.
  - shoot.mjs screenshot journeys at 390/768/1440 + "you have looked at every frame"; chromadiff.mjs measures color drift vs the reference image; systemscan.mjs crawls every route, fails controls over variant budget, presses Tab for focus visibility, renders one tile per variant.
  - README: 10 live showcase sites claimed at 0 fails/0 warns, one built by a different model (Kimi K3) as a portability test; explicitly "no benchmark numbers anywhere in this repo" — the linter result is the one reproducible claim.
- 3 non-obvious ideas worth adopting:
  1. House-tells (field 7): the skill names its OWN recurring authorial tics (near-black bg, mono service labels, amber accents — "measured across nine showcase builds, eight were dark") and forces each build to break two — self-aware anti-style-drift at the author level, not just the AI level.
  2. Second-order reflex check: predicting what "a generic AI avoiding the obvious cliché" would do (fintech → terminal dark mode is also saturated) and deviating from both — encoding the adversarial regression of taste.
  3. Measurement honesty embedded in tool comments: DPR-2 production-build FPS as the only real number, "headless reporting 0 console errors is not a pass", dev-server frames "describe a page nobody will ever load" — perf literacy baked into the gate itself.
- Flaws / weaknesses:
  - Single-author aesthetic risk is acknowledged but real: the showcases lean heavily cinematic/WebGL; the "system" register for boring admin UIs is the least proven path.
  - Linter is regex-based ("no full parser needed") — CSS-in-JS, template literals, and unusual formatting can evade it; it measures tokens, not rendered pixels (that's shoot/motionqa's job, which requires Playwright install).
  - Russian strings in routing examples and some copy; bilingual but inconsistent for an English-first repo.
  - motionqa's honest requirements (headed + production build) make it hard to run in CI/headless environments by its own admission.
  - Asset generation depends on external local CLIs (agy/codex/grok, ffmpeg, MiniMax) — availability not guaranteed.
