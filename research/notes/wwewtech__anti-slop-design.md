# wwewtech/anti-slop-design — deep-read notes
- Verified: TBD★ (metadata not yet in CSV), license MIT, last push not verified, branch main (source: GitHub API search 2026-11-24)
- What it is: A single prompt-only agent skill ("Autonomous Principal Design Technologist and Anti-AI-Slop Specialist") that bans 12 AI-slop anti-patterns and prescribes 4 fixed design archetypes, an 8-state interaction system, Emil Kowalski-derived motion rules, and a 7-axis self-graded quality gate. Ships only markdown (SKILL.md duplicated at root and skills/anti-slop-design/, byte-identical) plus registry/launch files — no scripts, no detector, no tests of output quality.
- Scope: UI only (SaaS dashboards, landing pages, mobile); no prose-slop rules beyond vanity stats
- Key files read: README.md (full), SKILL.md (head 60; identical to skills/anti-slop-design/SKILL.md per diff), skills/zzprobe-in-working-repo-5e18/SKILL.md (full), SKILLS_ANALYSIS_AND_AUDIT.md (head 40), evals/evals.json (head), .github/workflows/validate-skill.yml (head), COLLECTIONS.md/LAUNCH_KIT.md (presence)
- Mechanics:
  - 12 anti-pattern ban matrix (AI dark-mode radial-gradient blob, slate/indigo monotony, cookie-cutter 3-card grid, emoji-as-icons, fabricated vanity stats, screaming eyebrow labels, single-word italic/gradient accents, metric duplication, card-level filter pollution, vanity space-wasters, missing interactive states, broken placeholders) each with a "mandatory production replacement".
  - Core UX axioms: "1-to-3 rule" (1 primary action, max 3 secondary per zone), "85% statistical prioritization law", strict ban on duplication, "mobile linearity on desktop".
  - 4 fixed archetypes (Quiet Luxury SaaS, Technical Dense Terminal, Editorial & Refined, Warm Tactile) — the README/SKILL print literal fixed hex palettes (e.g. `--bg-canvas: #09090b; --accent-primary: #3b82f6`) despite the banned-matrix simultaneously telling you to use "curated semantic tokens (OKLCH/HSL) with distinct brand personality" — an internal contradiction.
  - 8-state interactive feedback system (default/hover/focus-visible/active/loading/error/success/disabled); motion rules credited to Emil Kowalski (0ms for 100+/day actions, 120-180ms standard, never ease-in, `:active { transform: scale(0.97) }`).
  - 7-axis pre-emit quality gate self-graded by the agent (anti-slop purity, UX speed, typography, spacing math, motion, a11y, responsive) with ">= 4/5 across all 7 axes mandatory before shipping" — entirely model-self-graded, nothing measured.
  - evals/evals.json: 3 hand-written prompt/expected_output pairs (de-slop a dashboard, 50ms hero, 8-state button) with `"files": []` — descriptions of desired behavior, no runner, no assertions.
  - CI (validate-skill.yml) only validates SKILL.md frontmatter/schema with an inline Python regex check.
  - zzprobe-in-working-repo-5e18: a deliberate leftover test artifact — "A uniquely named probe skill added to an already indexed repository, used to test whether install counting is per-repository rather than per-skill" with filler prose "Original prose about tactile feedback latencies in capacitive haptics overlays" and dummy steps. It exists to measure/game skills.sh install-count attribution, and was left in the published repo.
- 3 non-obvious ideas worth adopting:
  1. The "85% statistical prioritization law" as a sharpened restatement of frequency-based UX prioritization (make the 85% path one click; push the 15% edge cases into secondary popovers) — a usable density heuristic.
  2. The 8-state interaction contract as a compact completeness checklist for every interactive primitive (most skills only demand hover/focus).
  3. Framing UX quality as task-completion speed rather than aesthetics — "commercial speed & logic engine" — which pairs well with anti-slop metrics.
- Flaws / weaknesses:
  - No enforcement whatsoever: no scanner, no browser check, no runner for its 3 evals; the 7-axis gate is the agent grading its own homework. The repo is prompt text plus marketing.
  - Registry-growth fingerprints: the zzprobe install-count test artifact, LAUNCH_KIT.md, COLLECTIONS.md with "markdown snippets for awesome-lists", README sections bragging about being indexed in 5 skills.sh topics and "Google Antigravity Built-in Skills" — the repo optimizes for listing penetration, not verified capability.
  - The "audit of 100+ skills" claim: SKILLS_ANALYSIS_AND_AUDIT.md (122 lines) is a narrative 5-category table plus "8 fatal flaws" prose citing ~6 named repos; it is not a benchmark with measurements — the 100+ number is unverifiable from the repo.
  - Fixed hex palettes contradict the token-curiosity advice and would stamp every adopter with the same "Quiet Luxury SaaS" look — recreating convergence; only 2 of 4 archetypes' palettes are even shown.
  - Unverified stars/metrics (TBD); vague attributions ("Real-world SaaS critiques from Kole Jain, ALETI landing page analyses").
