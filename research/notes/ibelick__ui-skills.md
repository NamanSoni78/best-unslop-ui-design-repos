# ibelick/ui-skills — deep-read notes
- Verified: TBD (metadata pending). Branch `main` (tarball path). MIT, "Copyright (c) 2026 Julien Thibeaut" (LICENSE). Unusual shape: this is not just a skill folder — it is a full Astro + Cloudflare web app (package.json v0.2.4, wrangler.jsonc, D1 migrations, better-auth, tests, scripts for registry checks and GitHub metadata) that hosts the ui-skills.com registry, plus a CLI (`npx ui-skills`) and MCP endpoint, plus the 10 skills themselves.
- What it is: A "Skills for Design Engineers" pack with a self-hosted distribution layer: 10 skills addressing UI cleanup, design-system capture, accessibility, motion performance, metadata, canvases and device frames, served through a website, CLI and MCP server. The skills are methodology-heavy, written like verification procedures with proof gates rather than taste guidance.
- Scope: UI (audit/fix orientation; registry adjacent).
- Key files read: README.md; skills/improve-ui/SKILL.md (116 lines, full); skills/fixing-accessibility/SKILL.md (135 lines, full); skills/create-design-md/SKILL.md (254 lines, full); skills/component-canvas/SKILL.md (123 lines, full); skills/ui-skills-root/SKILL.md (59 lines, full); descriptions of the remaining 5; package.json.
- Mechanics:
  - improve-ui: a read-only UI auditor with an evidence discipline that is the strictest I have read in this batch. Boundaries: never modify product source (only writes under `design-plans/`), no installs, no commits. Findings must pass three named proofs — Contract (a binding design decision or an in-surface contradiction; "'Prefer,' 'generally' ... do not establish a contract", improve-ui/SKILL.md:53), Runtime (the cited token/owner provably reaches the surface through the traced render path), Correction (one deterministic change; if evidence can't determine the right choice, reject). Then a falsification pass re-opens every cited source and deletes candidates on 6 listed conditions. Reports max 3 findings ordered by confidence/impact/reach/cost, and "another agent executes" the plans it writes — separation of audit and implementation.
  - create-design-md: reconstructs a DESIGN.md (design language doc with YAML token frontmatter) from a repo or a public URL. Two modes with different evidentiary strength (repository evidence can establish norms; URL evidence only observable patterns). URL mode requires all three proofs (observation, basis, consequence) before any claim; computed styles or loaded declarations required for exact values; frontmatter shape is a hard gate (typography scales must be mappings with fontFamily/fontSize/lineHeight/fontWeight fields, flat color tokens matching `^[a-zA-Z0-9][a-zA-Z0-9-]*$`); validation via external tool: `npx @google/design.md lint` and `--export` (css-tailwind / json-tailwind / dtcg targets), with a required no-op pass deleting vague advice ("be thorough", "use good judgment"). Drafts are private until lint+export pass.
  - fixing-accessibility: 9 priority-ordered rule categories (accessible names, keyboard, focus/dialogs, semantics, forms, announcements, contrast, media/motion, tool boundaries), minimal-fix doctrine ("prefer native elements before adding aria", "do not add aria when native semantics already solve the problem"), before/after HTML snippets, review format quoting the exact violating line.
  - component-canvas: builds a pan/zoom canvas that wraps the project's real components ("The canvas wraps components. It never changes them"), variant comparison rules (one prop at a time, same wrapper/data/theme), real pointer/keyboard state testing, safety for previews (mock providers, never production credentials), camera persistence, and an honest report format: "A check counts as passing only if it was run. If a check was skipped, say so."
  - The other skills: baseline-ui (fast "deslop" cleanup pass for spacing/hierarchy/typography), create-canvas (freeform explorer), device-frames (device-framed screenshots/mockups), fixing-metadata (page metadata), fixing-motion-performance (layout thrash, compositor props, scroll-linked jank).
  - ui-skills-root: a routing skill ("routing layer") with a selection protocol — prefer 1 skill, never more than 3, route by topic→stack→specificity — surfaced by `npx ui-skills start`.
  - Distribution: CLI commands (start/categories/list/get), MCP tools `list_skills`/`get_skill` at ui-skills.com/mcp, a public "playbook" of distilled lessons; the repo runs registry-quality scripts (check-registry-skills, precompute-agent-skills-digests, update-github-metadata) — the site is a curated small registry, not just docs.
- 3 non-obvious ideas worth adopting:
  1. The three-proof gate (contract + runtime + correction) and mandatory falsification pass — a general pattern for making agent design audits say "no supported findings" instead of inventing plausible problems.
  2. DESIGN.md as a persistent, lint-validated, exportable design-language artifact that gives future agents verifiable context — with URL-mode reconstruction guarded by "computed value + loaded declaration agree, or recurrence across samples".
  3. Honest reporting contract ("A check counts as passing only if it was run") applied to every build/report cycle.
- Flaws / weaknesses:
  - Verbosity/bureaucracy: create-design-md spends more words on schema policing and YAML shape rules than on design content; the ratio of process to payoff is high, and the hard dependency on an external `@google/design.md` npm tool is a fragile external contract (not vendored; spec is fetched at runtime).
  - The skills teach audit discipline, not taste — nothing here gives aesthetic direction, so as an "unslop" resource it prevents bad findings, not generic design.
  - Repo doubles as a production web app (auth, D1, telemetry-adjacent scripts); the skill content is a minority of the tree, so consumers must trust a much larger surface than the 10 SKILL.md files.
  - fixing-accessibility is solid but conventional (WCAG checklist); improve-ui explicitly discards a11y findings to avoid overlap.
- Safety & license: MIT. No hooks, no telemetry in the skills; the skills are prose-only (no executable scripts found under skills/). improve-ui/create-design-md/component-canvas are deliberately read-only or narrowly-scoped with explicit do-not-mutate boundaries — the safest write posture in this batch. External npx calls (`@google/design.md`, `ui-skills` CLI) are documented commands, not auto-run. SECURITY.md present at root.
