- 3 non-obvious ideas worth adopting:
  1. Commit-pinned vendoring with weekly drift checks and a standing "Upstream skills moved" issue — the correct way to aggregate moving upstreams without silent rot or silent edits.
  2. The "ratchet" (CI-pinned tell count that may only shrink) and the "second-order defaults" list — anti-slop that anticipates its own success creating a new monoculture (cream+terracotta as "the new default, not a direction").
  3. Direction gate before remediation: "The rest of this skill removes mistakes; it does not give a screen character" — separating de-slopping from art direction, with show-and-wait owner approval.
- Flaws / weaknesses:
  - Mostly vendored by design: the design/motion/ux substance is other people's work; Molveau's original layer is routing, gate, tells, and Québec/SEO verticals. Value is curation + plumbing, not new design knowledge.
  - Ambitious attack surface: plugin + hook + MCP server + hosted endpoint + agents + commands — more moving parts than a skill pack needs; the hook ships ON by default (opt-out via /config).
  - Vendored copies may contain upstream instructions the anti-slop SKILL.md must override ("take the guidance, skip pointers to missing tools", SKILL.md:12) — stale pointers are a real risk when scripts/library are excluded.
  - 18 skills is a lot of context to route correctly; relies on the user or agent picking the right one (mitigated by workflow/ui "Neighbors" routing and /design-grill cost warnings).
  - seo/geo report closing line "names Mention, the studio's service" (CHANGELOG 1.8.1) — mild self-promotion inside skill output.
- Safety & license: scripts execute (Node .mjs: detect-tells, check-motion, fr-typo, check-writing, sync-sources, stats, hook-check) — all zero-dependency, documented, and MCP is read-only with no network; but the PostToolUse hook auto-runs on every Edit/Write in Claude Code (on by default with the plugin). Telemetry: none of its own; README points to skills CLI's anonymous install counts.
