- What it is: A domain-expert skill pack for UI motion and design engineering by Emil Kowalski (author of Sonner and Vaul — Sonner authorship is self-evidenced in-repo by the ask-sonner skill: "my toast library", README.md:63; Vercel/Linear background claimed at README.md:13). - Mechanics:
  - Every skill opens with a scripted "Initial Response" ("I'm ready to build animations that feel right, my knowledge comes from Emil Kowalski's animation philosophy", animate/SKILL.md:12) and a scoping paragraph that says what this skill does NOT do, naming the sibling skill that owns that job — the pack is a routing lattice, not 20 loose files.
  - animate: a gated build sequence — (1) frequency gate (100+/day actions: "No animation. Ever."; keyboard-initiated is "a disqualifier, not a judgment call", citing Raycast); (2) purpose must be named in one word from a fixed list (feedback, spatial consistency, state indication, preventing jarring change, explanation, delight — delight only at rare/first-use tier); (3) cheapest-tool ladder (CSS transition → @starting-style → CSS animation → WAAPI → Motion); (4) properties: transform/opacity only, "Never `scale(0)`", transform-origin at the trigger for popovers (modals exempt); (5) exact easings: `cubic-bezier(0.23, 1, 0.32, 1)` ease-out, `(0.77, 0, 0.175, 1)` in-out, `(0.32, 0.72, 0, 1)` drawer; "Never `ease-in` on UI"; exact durations per element class (button press 100–160ms, tooltips 125–200ms, dropdowns 150–250ms, modals/drawers 200–500ms; "UI animations stay under 300ms"); springs `{duration: 0.5, bounce: 0.2}` with bounce 0.1–0.3; (6) interruption (transitions not keyframes for rapid triggers, exit the way it entered); (7) reduced-motion + hover gating ship with the code. Ends with a "Never Ship" table (12 auto-block rows) and a short output contract (gate result, ingredients, what to feel-check — "play it at 2–5× duration", test on a real device, "look again the next day").
  - choreograph: the multi-element layer. Lead/Support/Decoration/Static role casting, a binary decision tree for Together/Overlap/Sequence/Carry, "One entrance per container" and "Uniform stagger is forbidden" as hard rules, product-UI stagger budgets 30–80ms with total under ~300ms, duration scaling by distance `clamp(0.15s, Δheight / 500, 0.27s)`, exits simultaneous and simpler, interruption test list, required timeline table output including a "What doesn't move, and why" section.
  - break-ui: adversarial worst-case-data testing. Persona: "the most annoying real user" with concrete names/emails; hard rules (plausible or schema-backed values only, "Change the data, not the component", dev-only toggle, report before fixing). A failure-signature table maps symptom→cause→fix (flex-shrink squished avatars, `min-width: 0`, `overflow-wrap: anywhere`, Intl.PluralRules for "1 members", tabular-nums, initials via Intl.Segmenter). Truncate/wrap/clamp decision per field; severity scale Broken/Ugly/Fragile.
  - animation-vocabulary: reverse-lookup glossary (~120 terms, 11 sections) from feel-words ("the bouncy thing when a popover opens") to exact terms; disambiguation rules (Pop in vs Bounce, Morph vs Shared element transition); instruction to quote the glossary verbatim.
  - emil-design-eng: the umbrella philosophy skill (684 lines): taste-is-trained, unseen-details-compound (Paul Graham quote), mandatory Before/After/Why markdown-table review format, the animation decision framework (duplicated and extended from animate), springs incl. useSpring mouse tracking, component micro-rules (scale(0.97) on :active, tooltip skip-delay on subsequent hovers), clip-path recipes, gesture physics (momentum, damping at boundaries, friction), performance (CSS vars are inheritable, Motion 14.2 acceleration caveat), a11y section.
  - Also notable: learn-taste (README.md:61) persists every design correction you make into a DESIGN.md as rules-with-reasons; remove-animations is the anti-feature skill (kill fade-ins on every section, tooltip delays); pick-ui-library routes to trusted libraries instead of hand-rolling.
- 3 non-obvious ideas worth adopting:
  1. Frequency-gated motion ("should this animate at all" as step 1 with a table that can output "no code") — motion restraint encoded as a hard gate rather than a value statement.
  2. "Never Ship" self-check tables that mirror the review skill's auto-block list — construct skill and review skill enforce the identical bar, so output is written to pass review first time.
  3. break-ui's "plausible or schema-backed, never random" worst-case data rule plus the persona with real-looking multi-part names — turns edge-case testing into credible, designer-respectable evidence.
- Flaws / weaknesses:
  - Single-author taste presented as universal law; no benchmarks or evals anywhere in the repo — the "strict review" is rule-matching, not measurement.
  - Numbers are asserted, not sourced (durations, curves); "iOS-like drawer curve (Ionic)" is the only attribution pattern.
  - Heavy duplication between emil-design-eng and animate/review-animations (the decision framework appears at least twice) — install both and context weight doubles.
  - Web/React-first; the Expo/Swift coverage exists but is a parallel track. Initial-Response ritual ("respond only with...") wastes a turn and is persona theater.
