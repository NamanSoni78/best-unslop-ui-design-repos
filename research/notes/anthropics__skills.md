- What it is: Anthropic's official example-skills repository: a demo collection of Claude Agent Skills spanning document processing (docx/pdf/pptx/xlsx), design, dev tooling and comms, plus the Agent Skills spec pointer and a skill template. It is a reference for "what a skill looks like", not a curated quality list. For us, the single important file is skills/frontend-design/SKILL.md — the canonical origin of the modern "avoid AI-look UI guidance" genre.
- Scope: official-collection (frontend-design = UI; canvas-design/algorithmic-art = visual art; rest is non-UI).
- Key files read: README.md; skills/frontend-design/SKILL.md (71 lines, full); skills/canvas-design/SKILL.md (129 lines, full); skills/algorithmic-art/SKILL.md (404 lines, first ~200); .claude-plugin/marketplace.json; spec/agent-skills-spec.md (stub — points to agentskills.io); THIRD_PARTY_NOTICES.md (head).
- Mechanics:
  - frontend-design is pure prose, one file, no scripts, no reference files, no images. Structure: (1) design-studio-lead persona with an already-rejected-cliché client framing; (2) "Ground your designs in the subject matter" — derive the aesthetic from the product's industry/materials/vernacular, confirm subject before designing; (3) Design principles — hero as "the most characteristic thing in the subject's world", typography carries personality, line lengths < 80 chars, explicit banned default type treatments (single-word accent in a headline, ALL-CAPS labels, unnecessary eyebrow labels); structural devices (01/02/03 markers) only when content is actually a sequence; non-user-triggered motion "sparingly", with fade-and-slide-up-per-section and hover-on-every-card named as the generic default; (4) Process — a 5-item calibration list of what AI-generated design clusters around, quoted essence: "a warm cream background (near #F4F1EA) with a high-contrast serif display and a terracotta or warm-clay accent (often near #D97757" (SKILL.md:39, also flags near-black+acid-green, broadsheet hairline style, the "SaaS-card kit", and template chrome: tracked ALL-CAPS eyebrows, 'A · B · C' middle dots, 'WORD — fragment' em-dash labels, #0B0B0B pseudo-black, monospace data labels, '→' on links); then a two-pass workflow — brainstorm a token plan (4–6 named hex colors, type roles, one-sentence layout concepts + ASCII wireframes, principles), review the plan against the brief for "would I produce this for any similar page", only then code; CSS selector-specificity warning; (5) Restraint — "Spend your boldness in one place", quality floor (responsive, keyboard focus, reduced motion, accessible palettes), screenshot self-critique ("a picture is worth 1000 tokens"), Chanel remove-one-accessory advice; (6) writing-in-design — words as UI content: active voice, CTA says what happens ("Save changes," not "Submit"), stable vocabulary across a flow, "Errors don't apologize, and they are never vague" (SKILL.md:69).
  - canvas-design: two-phase "design philosophy" generator — write a 4–6-paragraph art-movement manifesto, then express it as a single .png/.pdf; heavy repeated "craftsmanship" incantations ("labored over with care", instructed to be repeated), a "subtle niche reference" jazz-quote concept, fonts from a local ./canvas-fonts dir, and a fake final user quote pushing a second polish pass.
  - algorithmic-art: same philosophy-first pattern for p5.js; seeded randomness (Art Blocks pattern), parameter dicts, and a mandated templates/viewer.html starting point with fixed Anthropic branding (Poppins/Lora, sidebar Seed→Parameters→Actions).
  - The 19 skills: academy-guide, algorithmic-art, brand-guidelines, canvas-design, claude-api, discernment-nudge, doc-coauthoring, docx, frontend-design, internal-comms, mcp-builder, pdf, pptx, skill-creator, slack-gif-creator, theme-factory, web-artifacts-builder, webapp-testing, xlsx.
  - skill-creator ships a real eval harness (run_eval.py, aggregate_benchmark.py, improve_description.py) — the only quality-measurement machinery in the repo.
- 3 non-obvious ideas worth adopting:
  1. The plan-review gate: force the model to write a token/layout plan and then adversarially re-check it ("work through a similar prompt to see if you arrive somewhere similar") before any code is written — cheap self-similarity test for genericness.
  2. The 5-trait calibration list is written as observed model output clusters with hex values and specific typographic tics (middle-dot meta strings, 'WORD — fragment' labels), not vague "be distinctive" advice — it is checkable.
  3. "The brief's own words always win, including when it asks for one of these looks": banned-tells lists explicitly yield to user direction, which prevents anti-slop rules from overriding intent.
- Flaws / weaknesses:
  - "Demo purposes only" disclaimer; README explicitly says behavior may differ from production Claude (README.md:24) — no evals back any design skill.
  - frontend-design has no scripts, no visual references, no recipes — effectiveness is unmeasured and unverifiable in-repo.
  - canvas-design/algorithmic-art lean on repeated "master-level craftsmanship" incantations — prompt-superstition rather than mechanics; they read as LLM-psychology tricks.
  - brand-guidelines is Anthropic-internal by nature; discernment-nudge is a behavioral nudge unrelated to design quality.
- Safety & license: no hooks, no telemetry, nothing auto-runs; document skills contain many Python/JS scripts (pptx/pdf/xlsx, skill-creator evals, webapp-testing drives Playwright) but all are user-invoked. Apache 2.0 per skill; THIRD_PARTY_NOTICES.md covers vendored dependencies (incl. GPL v3 components, worth noting for redistribution). No attribution requirements beyond notices.
