# heydamir/unslop — deep-read notes
- Verified: 21,001★, license CC-BY-4.0, last push 2026-11-15, branch main (source: GitHub API search 2026-11-24)
- What it is: A single-skill repo by Damir Sokolovsky (author of the "Unslopping" viral X series) that turns vibecoded, AI-looking UI into a designed interface via a designer-style "redline review" in nine ordered passes. Distinguishing features: a pre-edit direction the user must approve, a snapshot script to work from a bare URL, and a story-video generator that renders the screen "unslopping itself" as a shareable square video.
- Scope: UI (dashboards/apps/landing pages; copy pass exists but is UI copy, not general prose)
- Key files read: README.md, skills/unslop/SKILL.md (full 236 lines), references/signs.md (head), references/tokens.md (head), references/refs.md, agents/openai.yaml, scripts/snapshot.mjs (head 50), scripts/story.mjs (head 40 + grep of step/redline mechanics), scripts/story-path.mjs (full), test/story.test.mjs (head)
- Mechanics:
  - Run flow: look at the screen (screenshot if possible) → audit against references/signs.md (each sign paired with its fix) → triage heavy/light/no slop (polish mode for light, plain honesty for no slop: "Never change a good screen just to make it different") → write a 5-line direction (Product/Character/World/Moments/Signature) and STOP for user approval → fix in nine passes in strict order: Spacing, Color, Icons, Copy, Type, Layout, Details, Visuals, Motion → checklist → report → optional story video.
  - The direction is anti-template by construction: Character words like "clean, modern, sleek, minimal, premium" are banned because "they describe every template"; each run derives World/Moments/Signature from the product itself; final checklist has a "template check" (swap the product name — would the screen still fit?).
  - Core philosophy: "slop spreads richness over the chrome; craft keeps chrome quiet and puts richness into one or two moments of content" — one bright element, quiet chrome, one accent, three text roles from one tinted neutral ramp, hairline borders at 6-10% opacity, nested radius math, 4px spacing grid, no hue-to-hue gradients ever.
  - The 9 scripts story (actually 3 scripts + 3 tests, 6 .mjs files):
    1. `scripts/snapshot.mjs` (197 lines) — saves a live site or local HTML to `unslop/original.html` via Playwright: scrolls the page first so lazy-loaded content is captured, inlines external stylesheets by fetching them (network use), emulates dark/light, also writes `original.live.png` to compare rendered copy vs saved copy (script-driven animated backgrounds don't survive, so audit them from the live shot).
    2. `scripts/story.mjs` (505 lines) — renders the story video: serves story.html from a local 127.0.0.1 HTTP server (path-safe), validates the `<meta name="unslop-steps">` and `unslop-frame` camera meta, warns on >8 text swaps, >5 data-slop marks, wrong data-radius/data-gap counts, then drives Playwright frames + ffmpeg to mp4; `--play` loops it live in a browser; story mechanics are pure CSS-class stacking (.s1/.s2 accumulate) so values tween in place — "nothing is swapped, everything morphs", with a wave stagger and redline overlays (data-gap measurements counting live, data-radius corner outlines, data-slop tags).
    3. `scripts/story-path.mjs` (27 lines) — path resolver for the story server that blocks traversal and symlinks (realpath both sides, reject root itself); notably careful for such a small file.
    4-6. `test/*.test.mjs` (node:test) — story.test.mjs splices meta variants and asserts error messages; story-path.test.mjs covers the resolver; snapshot.test.mjs covers the snapshot script. Tests run the real scripts via spawnSync with 20s timeouts.
  - Story video carries an `unslop by @heydamir` credit baked in, per the CC-BY license.
  - Visuals pass: prefers showing the real product over generated images; generated scenes only for landing heroes via external image services (fal, Replicate, OpenAI images, Higgsfield) — "shows the prompt and asks before every paid generation", offers to connect one as an MCP server; RTL support via references/rtl.md (dir/lang, logical properties, mirrored layout, zero letter-spacing on Arabic).
- 3 non-obvious ideas worth adopting:
  1. The morphing story video as an artifact of the process: because every pass is a CSS value change, the same page can tween from slop to design in place with live-counting redline measurements — both a demo asset and proof the fix is systematic, not a rebuild.
  2. Direction-before-edits with a hard stop for user approval ("changing the direction later means redoing everything") plus honest triage that refuses work when there is no slop — governance that most skills lack.
  3. The sign→fix pairing in signs.md (every detected tell is listed with its concrete remedy and exact values) and the "template check" (swap-the-name test) as a final self-audit.
- Flaws / weaknesses:
  - No deterministic linter: the audit is the model reading signs.md; there is no checker enforcing the passes (contrast rule exists but is prose), so quality depends on the model's diligence — weakest enforcement of the set.
  - Single-author, portfolio-marketing repo (README ends with "Hire the unslopper" paid service; credit required in every copy); CC-BY-4.0 is an awkward license for code/skills — derivatives must carry attribution, which conflicts with how skills get bundled.
  - Story video needs Playwright + Chromium + ffmpeg installed; snapshot fetches external stylesheets from arbitrary URLs (minor SSRF-ish surface in CI contexts, local tool though).
  - Only 3 scripts; README's "6 scripts" framing counts tests. No evals, no CI on the repo itself beyond the node:test files.
  - Image-generation passes depend on external paid services not present in the repo.
- Safety & license: scripts not executed by me. snapshot.mjs fetches external CSS from the page being saved; story.mjs runs ffmpeg via execFileSync and binds a loopback HTTP server; no telemetry; no hooks (Claude plugin manifest only registers the skill).
