- What it is: A single `deslop` skill (SKILL.md + ~16 reference files + templates) that de-slops an existing screen or builds one without the AI look, built around asking-before-deciding, gray wireframes before pixels, and a 15-step cycle with 5 "Stop" checkpoints. Includes 4 documented real case studies and a 20-pair slop/fix gallery.
- Scope: UI (with a copy.md reference; UI-first)
- Key files read: README.md, LICENSE, skills/deslop/SKILL.md, reference/outside-look.md, reference/slop-examples/README.md, docs/cases/README.md, docs/cases/01-rootera-plant/README.md, repo tree
- Mechanics:
  - Three request sizes: Tweak (one element; short cycle, no wireframe/outside-look), Screen (full cycle), Flow (whole cycle + outside look on every path); escalation rule "if a Tweak starts changing organisation, move up".
  - 15-step cycle with mandatory Stops: role sentence ("This screen exists to ___. It is not the screen for ___."), signal identification shown BEFORE proposing fixes, gray HTML wireframes ("cheap to change here, expensive later"), implementation, Finish at graded doses, then a **second check** (the skill re-audits its own output "as if the screen were someone else's"), then an **outside look**.
  - Outside look: screenshot the screen, hand ONLY the image (never code/class names/intentions) to a fresh agent, ideally a different model; fixed first question on a small/blurred version; "where the answers diverge, the design failed, not the reader"; flows get one fresh agent per path; new agents each round because an agent that saw the previous version reads with the answers in its head.
  - Project memory in `.deslop/` (profile.md, taste.md with choices/rejections/approved exceptions, recipes.md as the "ruler"); skill folder stays stateless so updates don't clobber user data.
  - "Asking is the main thing": visual questions are always shown, never described; missing assets are asked for, never invented; recorded taste exceptions are honored by later audits ("Leave out the exceptions recorded in taste.md").
  - Cases live in docs/ deliberately OUTSIDE the installed skill: "proof of what the skill does, not material for the agent to imitate: an agent that reads approved screens starts reproducing their look."
- 3 non-obvious ideas worth adopting:
  1. The outside-look protocol with context quarantine: fresh agent (preferably different model), image-only handoff, fixed opening question on a blurred version, per-path agents for flows, new agents per fix round — a genuinely adversarial self-review loop.
  2. Keeping exemplar screens out of the skill payload so agents don't clone the house style — the cases are evidence for humans, not training fodder.
  3. "What stayed on purpose" in every case (e.g. the glow the author kept despite the checklist) — recording approved exceptions as first-class taste data that later audits must respect.
