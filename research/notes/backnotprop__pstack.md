Among the 59 skills sits one `unslop` skill, which is the only reason we looked. Confirmed: it is a PROSE-writing de-AI skill, not UI.
- Scope: prose (unslop only; the rest is general coding workflow — not evaluated per brief).
- Key files read: README.md (head, structure, install, mirror notes); skills/unslop/SKILL.md (41 lines, full); MIRROR.md (head); SYNC-LOG.md (head); LICENSE; skills/ listing.
- Mechanics:
  - unslop/SKILL.md: 34 numbered prose rules under `disable-model-invocation: true` (invoked only on request; in Codex via a per-skill agents/openai.yaml that sets allow_implicit_invocation: false, README.md:71). Rules cover: banned AI vocabulary (additionally, crucial, delve, enhance, foster, landscape, pivotal, showcase, testament, underscore, vibrant), "is/has not serves-as/boasts", no "not just X but Y", no forced threes, one name per thing, no "from X to Y" off a real scale, no em/en dashes, colon placement rules, sentence-case headings, no decorative emoji, straight quotes, no chatbot phrases, no praise openers, filler cuts, one hedge max ("may"), no generic conclusions, banned abstract-metaphor nouns ("substrate, wedge, vector, nexus, primitive, harness, surface, scaffolding, paradigm, ratchet, north star, flywheel", SKILL.md:33), mechanism-over-feeling, one idea per sentence, active voice, adverb cuts, plain words, no personified code, whole sentences with articles.
  - Deliberate numbering gaps with an explanation: "Rule numbers are stable ids that other skills cite. A removed rule leaves a gap." (SKILL.md:11) — rules are a citation surface for the rest of the pack (e.g. technical-writing requires unslop installed; blast-radius and others cite it).
  - Workflow: scan for the patterns, then rewrite, "Preserve meaning and match the intended tone" (SKILL.md:9). No script, no detector, no evals — pure instruction list.
  - Pack context: poteto-mode orchestrates other skills; skills are cross-referenced with explicit install tables (standalone vs install-together, e.g. technical-writing + unslop).
- 3 non-obvious ideas worth adopting:
  1. Stable rule IDs with intentional gaps so other skills can cite rule numbers as an API — cheap, durable cross-referencing for a growing rule corpus.
  2. `disable-model-invocation: true` plus a per-harness compatibility file (agents/openai.yaml) to keep an editing skill out of the model's startup context until explicitly called — a real context-weight hygiene pattern.
  3. The banned abstract-metaphor noun list (substrate/wedge/vector/nexus/...) — a prose tell family most de-AI lists miss because they only ban adjectives and openers.
- Flaws / weaknesses:
  - unslop is a bare rule list: no examples of good rewrites, no scoring, no tests — much thinner than theclaymethod or even molveau's writing skill for the same job.
  - Pack is sprawling (59 skills, principle-* family of 25+) and optimized for Cursor multi-model workflows; unslop is a minor citizen, cited by 3 other skills.
  - Mirror layer adds sponsorship banner content and sync machinery on top of upstream; users must trust two maintainers (Cursor's original + mirror's rewrites).
  - Some rules are stylistic opinion stated as law (no dashes ever, sentence-case headings, one hedge max) with no domain carve-outs — will damage legitimate register (legal/technical) more than gated scanners would.
