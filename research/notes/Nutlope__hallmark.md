# Nutlope/hallmark — deep-read notes
- Verified: 60,265★, license MIT, last push 2026-11-11, branch main (source: GitHub API search 2026-11-24)
- What it is: A design skill for Claude Code / Codex / Cursor / OpenCode (v2.0.0, "Powered by Together AI") that refuses to look AI-generated. It deals one of 50 "themes" (each a material spec, not a layout), builds pages around the visitor's job, and enforces a tiered gate system with a real linter (`sloplint.mjs`, 4,426 lines) plus a fresh-context subagent review. Made by Together AI (Nutlope).
- Scope: both (UI floor + copy gates 19/58/69), website/landing-page focused; "redesign/audit" verbs for existing pages
- Key files read: README.md, skills/hallmark/SKILL.md, references/gates.md (head 60 lines), references/themes/coral.md (head), scripts/lint-hook.mjs (head), eval/README.md, eval/briefs.json (via python), eval/judge.py (head), scripts/photos.json (metadata), site/themes/ listing
- Mechanics:
  - The Floor: 16 non-waivable rules numbered to gate IDs — tokens-only colour/fonts, no `transition: all` or animating width/top/left, no italic word in a heading, `overflow-x: clip` on html/body (never 100vw), `minmax(0,1fr)` for image grid tracks, `:focus-visible` on everything, reduced-motion fallback + script-off visibility, never invented metrics/testimonials/logo walls, no eyebrows/tracked-caps labels, no middle-dot meta strings, no purple-to-blue gradient / nested cards / emoji icons / fake browser chrome, hero + one sentence + action visible at 1280x800, ~80 words per screen, capped centred container, Hallmark stamp in first CSS lines, run sloplint before handing back.
  - Gate tiers: Floor (never waivable) / Reflex (a default the model falls into; waivable "on the record" with guard evidence + reason; 3 consecutive waivers = house style that belongs in design.md) / Finish (craft detail, answered, never blocking) / Ledger (repetition bookkeeping). Waivers live in a CSS comment stamp block; sloplint re-derives the guard and rejects boilerplate or <24-char reasons; "A waiver naming a Floor gate is rejected and the gate fires."
  - Theme dealing: `theme.mjs deal` offers 3 themes fitting the prompt that clear the log; each theme is ≤8KB md + jpg (e.g. coral: oklch tokens, General Sans, letterpress card controls, felt-desk material). "A theme is a material, not a plan" — it never sets content or order, so two prompts in one theme make two pages. `draw` deals page anatomy from the job (shape, hero posture, nav, footer, two compositions to leave out) with a mirror test: "would a neighbouring prompt get this exact combination?"
  - Anatomy-first build: pages are built from the category's real anatomy (menu/lineup/issues), never "a default run of figures, steps and an email band". Hero built and reviewed alone first; one "Signature" (the prompt's strongest real thing shown at its best) per page.
  - Redesign safety: `sloplint --before` records every link, field, handler and heading; `--kept` fails the redesign if one went missing; handoff is side-by-side before/after.
  - Verification: `sloplint.mjs --render` checks at 8 widths (puppeteer-core + Chrome), plus fresh-context subagent review whose first word (recapture/rebuild/fix/ship) is acted on; "verification is budgeted: one batched inspection, one fix batch, at most one confirming round".
  - Edit-time hook: `install-hook.mjs` adds a Floor-only lint to Claude Code; lint-hook.mjs only fires on files that carry the Hallmark stamp or live in a `.hallmark/` project (polite scoping), runs sloplint --tier floor on edit.
  - Photos: 755 openly licensed photos as metadata-only JSON (Commons-hosted; no image files in repo), each with license/author/subject/tags; credited on page; explicitly refuses stock sites "whose terms bar AI tools from picking their images".
  - Eval harness (real, in eval/, not shipped in the npm package): 8 core briefs (b1-b8, 30 entries total in briefs.json) including temptation probes (b4 fabricate metrics, b5 component routing, b6 no-vision capability check); gen-direct.py runs brief×model×pack matrix against bare APIs; gen-cli.mjs drives the real `claude -p "/hallmark <brief>"` binary parsing stream-json for conformance; score.mjs runs sloplint per run (floorClean flag); judge.py is a stdlib vision judge scoring 6 axes + judged gates + overall 1-10; report.mjs builds a gallery; run-matrix.py has a repair loop.
- 3 non-obvious ideas worth adopting:
  1. The three-tier gate semantics (Floor never waivable / Reflex waivable with re-derived guard evidence / Finish answered but never blocking) with retired gate numbers never reused — a governance model for style rules that admits rules are defaults-with-reasons without letting everything be waived.
  2. Waivers as first-class artifacts: written in the shipped CSS stamp block with gate + guard evidence + page-specific reason, machine-rejected when boilerplate, and "same gate waived on three consecutive builds is a house style, not an exception" — turns exception drift into a signal.
  3. The eval harness measures the skill, not vibes: conformance to stamp/reference-load discipline through `claude -p` transcripts, sloplint floorClean scoring of outputs, and an LLM vision judge on hero+mobile screenshots — plus temptation briefs specifically probing whether the skill prevents invented metrics.
- Flaws / weaknesses:
  - sloplint tiers are partially model-judged (J and R/J classes), so "deterministic" only applies to the M class; the floor's enforcement quality varies by rule class.
  - 50 themes with hard-coded token palettes is itself a convergence risk at scale (a dealt theme still stamps many pages with the same oklch tokens); the log/rotation mitigates but doesn't eliminate it.
  - Single-maintainer bus factor (Nutlope/Together AI marketing tie-in: "Powered by Together AI", comp step uses TOGETHER_API_KEY); eval Tier B experiments with open models are archived, so claimed generality rests mostly on Claude Code runs.
  - README star claims aside, the skill's ~154-line SKILL.md plus 27 reference files is a lot of prose for an agent to load; they mitigate with load-only-what-you-need discipline but it's a real cost.
  - "Made by Together AI" and imagegen comp path means some features assume their API; no telemetry statement in README (eval tooling reads API keys from env/keyFiles but that's dev-side).
