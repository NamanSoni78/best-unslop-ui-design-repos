- What it is: An explicitly-declared **synthesis** of three community skills — emilkowalski/skill (motion craft), pbakaus/impeccable (design rules + anti-slop bans), leonxlnx/taste-skill (brief-read, dials, design-system honesty) — deduplicated into one SKILL.md + 6 reference files, plus a zero-dep preflight scanner and an upstream-drift checker. The repo's distinguishing feature is forensic per-file provenance.
- Scope: UI
- Key files read: README.md, NOTICE, SKILL.md, scripts/preflight.mjs (head), scripts/upstream-drift.sh (head), reference/ listing, LICENSE, LICENSES/Apache-2.0.txt
- Mechanics:
  - "Iron Law: never ship the first version" — build → critique with fresh eyes → refine → pre-flight → ship; Step 0 "Design Read" one-liner before generating; three intensity dials (DESIGN_VARIANCE / MOTION_INTENSITY / VISUAL_DENSITY, baseline 8/6/4, overridden per surface-mode register: Persuade/Operate/Read/Experience).
  - preflight.mjs: HARD rules (exit 1) — em dash, `transition: all`, `scale(0)` entrances, outline-none without a same-selector `:focus-visible`, z-index 999-family magic numbers, raw scroll listeners, gradient text, >1px side-stripes, repeating-linear-gradient, feTurbulence, custom cursor; WARN rules (never affect exit code) incl. >3 font families, eyebrow-count > ceil(sections/3), h-screen, pure #000/#fff, fonts.googleapis.com link. Markdown files only run prose rules because reference docs legitimately *show* banned patterns in teaching examples.
  - Prose-vs-code rule split is reasoned in comments, with an upgrade path (parse fenced blocks per language, exclude "wrong example" blocks).
  - upstream-drift.sh: report-only (never fails the build) — checks the ported upstream files against sha256 pins; 404 → MISSING, offline → UNREACHABLE (no false drift).
  - Templates as proof: two self-contained HTML pages (swiss-report, depth-launch with ~575-solid isometric keyboard generated via the Anatomy kit, 60fps at 4× CPU throttle claim, lite version 23KB vs 930KB); GSAP loaded from CDN with Subresource Integrity.
  - The merger FIXES upstream bugs, documented per file in NOTICE: e.g. taste-skill's `leading-none` contradicted its own descender-clearance rule → changed to `tracking-tight leading-[1.1]`; impeccable's declared `@position-try` fallback was never actually applied → added `position-try-fallbacks: --flip-above`; removed a GSAP `ScrollTrigger.create` pin that conflicted with CSS `sticky`.
- 3 non-obvious ideas worth adopting:
  1. NOTICE-grade provenance: per-file license map with upstream repo, commit hash, and line numbers for every borrowed passage (e.g. "OKLCH / no-pure-#000-#fff bullets from pbakaus/impeccable skill/SKILL.md@e7e923c:62-63"), plus transitive attribution (impeccable ← Anthropic frontend-design).
  2. upstream-drift.sh as a maintenance pattern: pin sha256 of every ported upstream file, report OK/DRIFT/MISSING/UNREACHABLE report-only — merged skills usually rot silently; this makes rot observable without breaking CI.
  3. Merging-as-curation with bug fixes: the synthesis documents where it deliberately deviates from each parent (portfolio routed to Persuade instead of Experience; serif "very discouraged" default) — an editorial layer on top of vendored content.
- Flaws / weaknesses:
  - It is a derivative compilation, not an original methodology — nearly all the taste content is the three upstream skills; the added value is dedup, provenance, preflight.mjs, and fixes.
  - preflight.mjs is regex/token-level (same class of limitation as all linters here); the "em dash = HARD fail" rule is aggressive and will flag legitimate prose uses.
  - Small community (104★) and one maintainer; the templates are impressive but are the only build evidence — no evals/benchmarks.
  - "MIT AND Apache-2.0" per-file licensing is correct but operationally confusing for consumers who just want to know if they can use it (they can — both permissive, NOTICE satisfied).
  - Skill description is an enormous trigger-catch-all paragraph (marketing-ish).
